# 规范差异：底座身份与落后判定（base-identity）

## ADDED Requirements

### Requirement: 底座身份是交付内容的指纹
WHEN 平台记录一个项目当初交付在哪个底座上,
系统 SHALL 使用交付快照的内容指纹作为身份，而不是底座所在仓库的提交号。

#### Scenario: 同一内容得到同一指纹
GIVEN 底座 checkout 未发生任何改动
WHEN 连续两次计算交付快照指纹
THEN 两次结果相同

#### Scenario: 内容变化必然改变指纹
GIVEN 交付内容里任意一个文件的一个字节发生变化
WHEN 计算指纹
THEN 指纹随之变化

#### Scenario: 平台自身的提交不算底座漂移
GIVEN 平台目录里有新提交而底座交付内容一格未变
WHEN 判断某项目是否落后于当前底座
THEN 判定为不落后
AND 发起升级时被「已在当前底座」拒绝

#### Scenario: 指纹决定合并基准的锚点
GIVEN 一次交付完成
WHEN 打底座标记
THEN 引用名由内容指纹派生，指向那笔交付提交
AND 同名的既有标记原样保留、不移动、不删除

#### Scenario: 升级分支与内容一一对应
GIVEN 项目主干尚未合入上一轮升级
WHEN 按同一内容指纹再次发起升级
THEN 仍按「升级分支已存在则不覆盖」拒绝，并说明先去处理那条

### Requirement: 版本号为展示层，指纹为判定层
WHEN 界面需要向人说明底座版本,
系统 SHALL 同时给出人工声明的可读版本号与内容指纹，且判定与提示只依据指纹。

#### Scenario: 人读版本、系统判指纹
GIVEN 底座带有一份人工维护的版本号声明，且自上次发布后内容已被修改但未抬版本号
WHEN 查看底座读数
THEN 显示声明的版本号
AND 同时显示按当前内容算出的指纹
AND 落后判定使用指纹而非版本号

#### Scenario: 声明与内容不一致时说出来
GIVEN 版本号声明未随内容变化更新
WHEN 展示底座信息
THEN 界面提示版本号与指纹不成对，要求先核对版本声明再发布

### Requirement: 落后量说清可下发多少而不只是差多少提交
WHEN 展示某个项目落后于当前底座多少,
系统 SHALL 给出以内容差异计的可下发量，并在算不出来时明确表示算不出来。

#### Scenario: 给出可下发文件数
GIVEN 项目交付在旧内容指纹上，当前底座内容已变化
WHEN 读取该项目的底座状态
THEN 返回发生变化的交付文件数量
AND 返回目标内容指纹

#### Scenario: 算不出来时不冒充为零
GIVEN 底座源码不可读或指纹无法计算
WHEN 读取底座状态
THEN 相应字段返回空值而不是零
AND 界面显示「算不出来」

#### Scenario: 一格都不能自动下发时不制造噪音
GIVEN 本次合并结果里没有任何可自动写入的内容
WHEN 发起升级
THEN 不创建分支、不产生待审请求
AND 该次记录单独标为「没产生升级分支」
