# 规范差异：应用壳与宿主贡献点（app-shell）

## ADDED Requirements

### Requirement: 应用壳以依赖方式被宿主消费，而不是被复制
WHEN 平台前端需要底座的登录页、动态路由、外壳布局或品牌装配,
系统 SHALL 通过包依赖消费同一份壳源码，并禁止宿主持有任何一份壳的手写副本。

#### Scenario: 宿主注册自己的页面
GIVEN 平台有 `views/lowcode/**` 这类只有平台需要的页面
AND 壳只暴露贡献点而不认识这些路径
WHEN 宿主调用 `createScaffoldApp` 并申报一条路由贡献
THEN 该页面进入路由表且菜单能按 `sys_menu.component` 解析到它
AND 壳源码里不出现该页面的路径字面量

#### Scenario: 宿主扩展外壳而不修改外壳
GIVEN 平台需要在顶栏显示「已切换租户」指示
WHEN 宿主通过插槽填入该内容
THEN 外壳组件文件未被修改
AND 交付项目拿到的外壳与平台用的外壳是同一份源码

#### Scenario: 拒绝以拷贝换取便利
GIVEN 有人为了让平台多一个入口而修改了壳组件的条件分支
WHEN 底座目录的单向依赖检查运行
THEN 该改动被识别为宿主语义侵入底座并被拒绝
AND 提示改走贡献点或插槽

#### Scenario: 断点一类的共享常量不得各有副本
GIVEN 窄屏断点在物料包内已有单一来源
WHEN 检查壳与宿主两侧的样式与脚本
THEN 不出现第二处写死的同一数值

### Requirement: 后端装配只住一处
WHEN 底座与平台各自需要可运行的启动模块,
系统 SHALL 把公共装配（安全配置、过滤器顺序、扫描清单、种子数据口径）集中在一个库模块里，两个启动模块各自只声明自己那部分。

#### Scenario: 启动模块可被复用而不引入不可依赖产物
GIVEN 底座启动模块产出的最终包是可执行形态
WHEN 平台模块需要复用它的装配
THEN 依赖指向那个库模块而不是可执行产物
AND 构建不因依赖可执行产物而失败

#### Scenario: 扫描清单各自独立
GIVEN 两个启动模块各自需要注册自己的映射接口
WHEN 应用上下文启动
THEN 每个模块只扫描自己列出的接口包
AND 不把包根写成扫描范围而把服务接口注册成映射接口造成装配二义

#### Scenario: 装配漂移被抓出来
GIVEN 有人在平台启动模块里重写了一份安全配置而不是复用装配
WHEN 后端全量套件运行
THEN 该重复声明被断言拒绝
